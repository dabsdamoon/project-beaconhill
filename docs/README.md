# Beaconhill Docs

Documentation is organized by **document kind**, not by topic or audience.

- **`design/`** — Plans, architecture, sequence diagrams. Forward-looking documents that describe what to build and why. Each file represents an intent or commitment.
- **`reference/`** — Stable how-to and lookup material. External library guides, brand identity, model selection notes, curated artifact lists. Each file answers "what is X?" or "how does X work?"
- **`notes/`** — Exploratory writing, analyses, comparisons, retrospectives. Lower commitment than `design/`; may become stale without harm.

## When adding a new doc

Pick the directory by asking:

1. Am I proposing a change to the system? → `design/`
2. Am I documenting something stable for future lookup? → `reference/`
3. Am I exploring or analyzing something? → `notes/`

If unsure, start in `notes/` and promote later.
